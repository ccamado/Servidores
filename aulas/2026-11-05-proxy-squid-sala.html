Proxy e Squid — quem intermedeia a navegação?

Conteúdo de continuidade após Firewall GNU/Linux. Esta é uma aula conceitual e de simulação no papel, sem laboratório.

1. O problema da rede escolar — 5 minutos

Em uma escola com vários computadores, podem existir políticas de acesso a sites. Uma solicitação de página não precisa chegar diretamente ao destino: um intermediário pode recebê-la, aplicar uma regra e então encaminhar ou recusar o pedido.

Pergunta: qual equipamento ou software pode intermediar esse pedido? Como distinguir uma restrição intencional de uma falha técnica?

2. Fluxo de um Proxy — 8 minutos

CLIENTE
Navegador→PROXY
Intermediário→SERVIDOR WEB
Destino

A resposta retorna pelo Proxy ao cliente. Ele pode aplicar regras de acesso, registrar solicitações e realizar cache, dependendo de sua configuração e do protocolo utilizado.

3. Proxy não é Firewall — 9 minutos

Podem trabalhar juntos?SimSim

Essas funções são complementares e variam conforme produto e configuração. A existência de um Proxy não substitui automaticamente um Firewall.

4. O que é Squid? — 7 minutos

Squid é um software livre de Proxy Web. Pode ser usado para controlar requisições, aplicar listas de controle de acesso e fazer cache de respostas, conforme a configuração. Não afirmar que todo tráfego HTTPS pode ser lido nem que todo acesso melhora de velocidade. O professor demonstra os conceitos no quadro.

7. Resumo para o caderno — 4 minutos

PROXY: intermediário entre cliente e serviço. SQUID: software livre de Proxy Web. FIREWALL: controla tráfego por regras de rede. JUNTOS: desempenham papéis diferentes e complementares. FLUXO: Cliente → Proxy → servidor Web → resposta.
